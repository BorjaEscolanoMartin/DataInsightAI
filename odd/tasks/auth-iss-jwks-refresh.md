# auth-iss-jwks-refresh

Objective: require the Supabase `iss`, normalize the SUPABASE_URL trailing slash and refresh the JWKS cache on an unknown kid.
Branch: `fix/auth-iss-jwks-refresh` from `main` (c08f2dc). Delivery: ask-on-risk, single PR expected. Runner: `pytest` in `apps/api`.

## Specs

- S1 Trailing slash: "El validador quita la barra y valida después. Añade el rojo: https:/// da ValidationError." The `supabase_url` validator strips trailing slashes (`rstrip("/")`), then applies the existing https check.
- S2 iss: "validar y exigir iss". The expected value is derived once from SUPABASE_URL: "es exactamente SUPABASE_URL + /auth/v1, sin barra final (https://<proyecto>.supabase.co/auth/v1)". Passed as `issuer` with `require_iss` in `jwt.decode`; the JWKS URL uses the same derivation.
- S3 JWKS refresh on unknown kid: "refrescar la caché del JWKS ante un kid desconocido", with a global cooldown between download attempts (failed attempts included) so "un atacante no pueda forzar descargas con kid inventados". An unknown kid within the cooldown is a 401 without downloading. Concurrent requests are protected with a lock and a re-check inside it (one download for N threads). "Un fallo al descargar sigue siendo error del servidor, nunca 401."
- S4 Max age: the cached JWKS expires after a max age, so a key removed from the JWKS stops being accepted. "Usa time.monotonic() para la caducidad y el límite de frecuencia, no time.time(), y parchea monotonic en los tests."
- S5 Stale fallback: "Si el refresco por caducidad falla y el kid está en la caché caducada, verifica con esas claves" and log a warning. Amended (L11): "el aviso se escribe una vez al fallar el refresco, no en cada petición que usa las claves antiguas, para no inundar los logs durante una caída de Supabase. El test debe esperar una sola línea para las dos peticiones." "El error del servidor queda solo para cuando el kid no está en caché o la caché está vacía."
- Constants (from Supabase docs, https://supabase.com/docs/guides/auth/signing-keys): max age 10 min (matches the Supabase client libraries' in-memory cache; with the 10 min edge cache, trust in a revoked key ends within the documented 20 min), refetch cooldown 60 s (the edge serves the same JWKS for up to 10 min, so refetching more often gains nothing).
