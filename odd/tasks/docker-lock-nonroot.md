# docker-lock-nonroot

Objective: install the API dependencies from uv.lock and run the containers as an unprivileged user.
Branch: `chore/docker-lock-nonroot` from `main` (0f507e1). Delivery: ask-on-risk, single PR expected. Checks: Docker builds and runs (no unit test runner applies); `pytest` in `apps/api` stays green.

## Specs

- S1 Lockfile install: "instalar las dependencias de la API desde uv.lock (hoy la imagen prod instala con pip install -e . sin fijar versiones)". uv pinned by version and digest (0.11.11, matching local), `uv sync --locked --no-install-project` (`--extra dev` only in dev), venv in `/opt/venv` outside the dev bind mount; prod built in two stages so the final image has neither uv nor build tools if they are not needed. A `pyproject.toml` change without relocking must fail the build.
- S2 PYTHONPATH: "Añade ENV PYTHONPATH=/app: sin pip install -e ., Celery y Alembic podrían no encontrar el paquete app. En las comprobaciones locales, confirma expresamente en los logs que arrancan la API, las migraciones de start.sh y el worker."
- S3 Unprivileged user: "ejecutar los contenedores con un usuario sin privilegios (Celery avisa de que corre como root, y los contenedores de desarrollo dejan ficheros de root en mi carpeta, incluido next-env.d.ts desde el de web)". API (prod and dev, hence the worker): user `app`, UID/GID 1000 (Borja's `id -u`/`id -g`), overridable with build ARGs; code under /app stays root-owned and read-only for the process; `PYTHONDONTWRITEBYTECODE=1`. "El usuario app debe tener un HOME propio con permisos (useradd -m o equivalente), para las librerías que escriben en ~/.cache." Web (dev only): user `node` (UID 1000).
- S4 .dockerignore: "con el .dockerignore en esta PR". `apps/api` and `apps/web` exclude `.env*`, local venvs, caches, `node_modules`, `.next` from the build context.
- S5 Verification. Local: prod target builds; relock check fails the build; `id` gives uid=1000; installed versions match `uv export --frozen --no-dev`; `/app` has no `.env`, `.venv`, `__pycache__`; `docker compose up --build`: `/health` 200, logs show the API, the start.sh migrations and the worker starting, worker without the Celery superuser warning; `docker compose run --rm api pytest` passes; `find apps -user root` empty after using web dev. Railway (Borja): build logs show `uv sync --locked`; migrations OK and `/health` 200; worker `celery@... ready` without the root warning; a real CSV upload completes; rollback by redeploying the previous deployment.
- "El volumen web_node_modules lo borro yo cuando llegue el commit 4."
